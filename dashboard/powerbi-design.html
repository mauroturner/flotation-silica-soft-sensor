Cómo armarlo en Power BI Desktop

  1. Instale Power BI Desktop (gratuito, solo para Windows) y abra un informe en blanco.
  2. Cree un parámetro de texto llamado CarpetaSalidas con la ruta de outputs\powerbi.
  3. Cree una consulta por tabla (20) con el código de la sección «Power Query»; deje el nombre de la consulta igual al de la tabla.
  4. En la vista de modelo, cree las 15 relaciones de la tabla «Relaciones»: uno a varios (1:*), filtro único de la dimensión al hecho, todas activas. Los hechos de la evaluación (fact_evaluation_summary, fact_variants y fact_leakage) no tienen relación de clave: alimentan sus propios visuales.
  5. Marque dim_date como tabla de fechas con la columna date; ordene month_name_es por month y horizon_es por horizon_key.
  6. Cree una tabla vacía llamada _Medidas y agregue en ella las medidas de la sección «Medidas DAX», con su formato.
  7. Cree las 5 páginas a 1280 × 720 px y ubique cada visual según la grilla de 12 columnas por 9 filas.
  8. Guarde el informe como .pbix. Cuando corra el flujo, «Actualizar» vuelve a leer los mismos archivos.
Qué se probó y qué no. Las pruebas del proyecto comprueban que los archivos cumplen el modelo (claves únicas, claves foráneas en su dimensión, relaciones de uno a varios con filtro único) y que cada tabla, columna, medida y función que nombra el DAX existe, que cada segmentador llega, por las relaciones, a los visuales de su página (o el título dice que no los filtra) y que todo texto de los datos está escapado. Ninguna medida se ejecutó: no hay Power BI en el proyecto, así que ninguna expresión DAX se evaluó. Las vistas previas se calculan con pandas sobre los mismos archivos, sin segmentadores; al armar el informe, compare cada tarjeta con su vista previa.
Una sensibilidad es una asociación del modelo, no una receta. Los sensores que pasan la compuerta de estabilidad se muestran con su signo; los demás dicen «sin asociación estable». Ninguna página dice qué hacer con un sensor.

7 dimensiones y 13 hechos. dim_hour filtra los hechos por hora; dim_date, solo la calidad de los datos por día. Los hechos de la evaluación sin clave de hora ni de sensor no tienen relación de clave.

Medidas DAX

Todas van en la tabla _Medidas. Los nombres de las medidas y los textos están en español; las tablas y las columnas, en inglés. Las cuatro medidas de las evaluaciones leen solo las filas selladas de la prueba: si no, una fila posterior al sello dejaría la cifra vacía.

Las dos medidas «de la última hora». «Última estimación» y «Último análisis llegado» toman el máximo de hour_key con CALCULATE y leen el valor en esa hora; solo reemplazan los filtros de las columnas de su hecho (hour_key, horizon_key), así que el segmentador de fecha, que filtra por la relación desde dim_hour, sigue valiendo: el máximo se toma entre las fechas elegidas. Se leyó el DAX; no se ejecutó. «Última estimación» es el horizonte 0: queda vacía si el segmentador de horizonte lo excluye.

Horas con análisis

Estimaciones (una por hora y horizonte) cuyo análisis fresco ya llegó; con el segmentador de horizonte, las de ese horizonte. Formato: #,0.

Horas con análisis =
CALCULATE ( COUNTROWS ( fact_estimate ), NOT ISBLANK ( fact_estimate[actual] ) )

MAE del modelo

Error absoluto medio del modelo en las estimaciones cuyo análisis llegó (% de sílice). Formato: 0.000.

MAE del modelo =
CALCULATE ( AVERAGE ( fact_estimate[abs_error] ), NOT ISBLANK ( fact_estimate[actual] ) )

MAE de la persistencia

Error absoluto medio de la persistencia (el último análisis fresco) en las mismas estimaciones. Formato: 0.000.

MAE de la persistencia =
CALCULATE ( AVERAGE ( fact_estimate[abs_error_persistence] ), NOT ISBLANK ( fact_estimate[actual] ) )

MAE de la base más fuerte

Error absoluto medio de B*, la base más fuerte de cada horizonte, en las mismas estimaciones. Formato: 0.000.

MAE de la base más fuerte =
CALCULATE ( AVERAGE ( fact_estimate[abs_error_b_star] ), NOT ISBLANK ( fact_estimate[actual] ) )

Modelo menos persistencia

Diferencia de los dos errores: negativa si el modelo se equivoca menos que la persistencia. Usa: [MAE de la persistencia], [MAE del modelo]. Formato: 0.000.

Modelo menos persistencia =
[MAE del modelo] - [MAE de la persistencia]

Sesgo del modelo

Media de la estimación menos el análisis: positiva si el modelo estima de más. Formato: 0.000.

Sesgo del modelo =
CALCULATE ( AVERAGEX ( fact_estimate, fact_estimate[estimate] - fact_estimate[actual] ), NOT ISBLANK ( fact_estimate[actual] ) )

Cobertura del rango

Parte de las estimaciones con análisis llegado cuyo análisis cayó dentro del rango del 80 %. Usa: [Horas con análisis]. Formato: 0.0%.

Cobertura del rango =
DIVIDE ( CALCULATE ( COUNTROWS ( fact_estimate ), fact_estimate[covered] = TRUE () ), [Horas con análisis] )

Última estimación

Estimación de la hora que cerró (horizonte 0) en la última hora estimada de las fechas elegidas; vacía si el segmentador de horizonte no incluye el 0. Formato: 0.00.

Última estimación =
VAR h = CALCULATE ( MAX ( fact_estimate[hour_key] ), fact_estimate[status] = "ok", fact_estimate[horizon_key] = 0 )
    RETURN CALCULATE ( SELECTEDVALUE ( fact_estimate[estimate] ), fact_estimate[hour_key] = h, fact_estimate[horizon_key] = 0 )

Último análisis llegado

Sílice del último análisis nuevo que llegó dentro de las fechas elegidas; el segmentador de horizonte no lo filtra. Formato: 0.00.

Último análisis llegado =
VAR h = CALCULATE ( MAX ( fact_hour_lab[hour_key] ), NOT ISBLANK ( fact_hour_lab[silica_pct] ), fact_hour_lab[lab_state] = "fresh" )
    RETURN CALCULATE ( SELECTEDVALUE ( fact_hour_lab[silica_pct] ), fact_hour_lab[hour_key] = h )

Horas sin estimación

Estimaciones que no se pudieron emitir por falta de entradas. Formato: #,0.

Horas sin estimación =
CALCULATE ( COUNTROWS ( fact_estimate ), fact_estimate[status] = "missing_inputs" )

Análisis frescos (%)

Parte de los análisis llegados que son nuevos (no repetidos ni interpolados). Formato: 0.0%.

Análisis frescos (%) =
DIVIDE ( CALCULATE ( COUNTROWS ( fact_hour_lab ), fact_hour_lab[lab_state] = "fresh" ), CALCULATE ( COUNTROWS ( fact_hour_lab ), NOT ISBLANK ( fact_hour_lab[silica_pct] ) ) )

Horas interpoladas

Análisis interpolados que ya llegaron, en los días elegidos. Formato: #,0.

Horas interpoladas =
SUM ( fact_data_quality[interpolated] )

Horas repetidas

Análisis repetidos (sin análisis nuevo) que ya llegaron, en los días elegidos. Formato: #,0.

Horas repetidas =
SUM ( fact_data_quality[held] )

Media del sensor

Media del sensor en las horas y los sensores elegidos; la fuente no dice la unidad. Formato: 0.00.

Media del sensor =
AVERAGE ( fact_hour_process[mean] )

MAE en la prueba

Error absoluto medio de un método en un horizonte, en la prueba y con la configuración sellada (si no, una fila posterior al sello vaciaría la cifra). Formato: 0.000.

MAE en la prueba =
CALCULATE ( SELECTEDVALUE ( fact_method_metrics[mae] ), fact_method_metrics[scope] = "test", fact_method_metrics[seal_state] = "sealed" )

Es la base más fuerte

Verdadero si el método es B*, la base más fuerte de su horizonte (se elige en V1). Formato: @.

Es la base más fuerte =
CALCULATE ( SELECTEDVALUE ( fact_method_metrics[is_b_star] ), fact_method_metrics[scope] = "test", fact_method_metrics[seal_state] = "sealed" )

Sensores con asociación estable

Sensores que pasan la compuerta de estabilidad: una asociación del modelo, no una receta. Formato: #,0.

Sensores con asociación estable =
CALCULATE ( COUNTROWS ( fact_sensitivity ), fact_sensitivity[passes] = TRUE () )

Veredicto

Veredicto de un criterio con la configuración sellada. Formato: @.

Veredicto =
CALCULATE ( SELECTEDVALUE ( fact_evaluation_summary[verdict_es] ), fact_evaluation_summary[seal_state] = "sealed" )

Semiancho del rango

Semiancho del rango del 80 % del modelo de un horizonte, calibrado en V2 (% de sílice). Formato: 0.000.

Semiancho del rango =
SELECTEDVALUE ( dim_model[half_width] )

Última fecha de cálculo

Instante de cálculo de la última corrida terminada bien. Formato: yyyy-mm-dd hh:mm.

Última fecha de cálculo =
CALCULATE ( MAX ( dim_pipeline_run[as_of] ), dim_pipeline_run[status] = "ok" )

Reglas bloqueantes fallidas

Resultados de reglas bloqueantes que fallaron, en las corridas cargadas. Formato: #,0.

Reglas bloqueantes fallidas =
CALCULATE ( COUNTROWS ( fact_validation ), fact_validation[severity] = "bloqueante", fact_validation[status] = "falla" )

Las cinco páginas

Cada página es un lienzo de 1280 × 720 px (16:9) sobre una grilla de 12 columnas por 9 filas; la posición de cada visual está en celdas. Las vistas previas de la evaluación muestran la prueba sellada si existe y, si no, la validación, y lo dicen. Un visual que un segmentador no filtra lo dice en su título.
